### Build routing

Use the playbook the user names. Otherwise, select one by the requested outcome.

| Requested outcome | Use |
| --- | --- |
| Add or change behavior | `./feature.md` |
| Fix behavior that is incorrect | `./bug-fix.md` |
| Change structure while preserving behavior | `./refactoring.md` |
| Improve a specific, measurable performance problem | `./perf-issue.md` |
| Create or update a Skill | `./authoring-a-skill.md` |
| Continue an authorized long task until a defined condition is met | `./autonomous-run.md` |
| Build and verify a PR queue, stopping before merge | `./autopilot-stack.md` |
| Build, verify, and merge a PR queue | `./autopilot-full.md` |
| Open a PR for existing changes | `./opening-a-pr.md` |
| Verify and land an existing PR or stack | `./shipping.md` |
| Reclaim space from worktrees or simulators | `./worktree-cleanup.md` |

Read the selected file and carry over the user's scope, any Plan handoff, and the acceptance checks. Apply `module-decoupling` to changes across internal modules. Follow the selected playbook's reply format. Route to automation, delivery, or cleanup only when requested; a route does not authorize commits, pushes, merges, deployments, or deletion outside that request.
